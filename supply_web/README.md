# أوامر التوريد — واجهة Next.js (`supply_web`)

الواجهة التشغيلية لمشروع أوامر التوريد. **أودو هو مصدر الحقيقة الوحيد**: لا تُخزَّن هنا بيانات أوامر أو أصناف.
يخزّن التطبيق فقط مستخدميه وأدواره وصلاحياتهم (SQLite محلي).

## كيف يعمل

```
المتصفح ──► Next.js (الخادم) ──► أودو  /json/2/supply.api/<method>   (مفتاح API في الخادم فقط)
              │                    └─► /supply_api/print/<kind>/<html|pdf|xlsx>/<id>
              └─ SQLite: المستخدمون، الأدوار، سجل التدقيق
```

- **الصلاحيات تُحدَّد هنا.** كل مستخدم له دور، وكل دور مجموعة صلاحيات قابلة للتعديل من *الإعدادات ← الأدوار*. تُفحص في
  الخادم (صفحات + Server Actions + مسار الطباعة)، والواجهة تُخفي ما لا يملكه المستخدم فقط للراحة.
- **أودو لا يعرف إلا حساب التكامل.** الشخص الفعلي يُرسَل في `context.ext_user_id` فيُسجَّل في الأمر وسجل التعديلات
  ("بواسطة أحمد عبر التطبيق"). كل مستخدم تطبيق يُزامَن إلى أودو (`ext_user_sync`) بدور `manager` لأن القرار هنا.
- **كل كتابة لها `idempotency_key`** تُولَّد مرة لكل نية مستخدم؛ الضغط المزدوج أو إعادة المحاولة لا يكرّر الأثر في أودو.
- مفتاح أودو لا يصل للمتصفح أبداً؛ الطباعة والتحميل تمر عبر `/api/print/...` بعد فحص الصلاحية.

## المظهر واللغة

- **وضع فاتح / غامق / حسب النظام**: زر في أسفل الشريط الجانبي (وفي شاشة الدخول). يُحفظ في cookie فيرسم الخادم المظهر الصحيح من أول لحظة بلا وميض.
- **عربي (RTL) / English (LTR)**: زر اللغة بجانبه. النصوص مكتوبة بالعربية في الكود وهي مفاتيح الترجمة (مثل gettext): `t("نص")`
  تعيد النص كما هو بالعربية، وتأخذ الإنجليزية من `src/lib/i18n/en.ts`. النص الذي لا ترجمة له (مثل رسالة ترجمها أودو نفسه
  أو اسم صنف) يظهر كما هو. المفاتيح التي فيها `{0}` تطابق نصوصاً بمتغيرات. رسائل أودو تُطلب بلغة الواجهة (`ar_001` / `en_US`).
  لمراجعة النقص: `node scripts/i18n-extract.mjs missing`.
- **الشريط الجانبي** يُطوى إلى شريط أيقونات لتوسيع مساحة العمل، ويُحفظ اختيارك.

## المسح بكاميرا الجوال

زر **الكاميرا** في شاشات: الإذن المخزني (العدّ)، وأمر التوريد (إضافة أصناف)، وأمر جديد. مبنية على أفضل الممارسات الحالية:

| الممارسة | كيف طُبّقت |
|---|---|
| فك الترميز على الجهاز | `BarcodeDetector` الأصلي حيث يتوفر (Chrome على أندرويد، الأسرع)، وإلا `zxing-cpp` WASM (مكتبة `barcode-detector`) من نطاقنا نفسه (`/wasm`) فلا CDN ولا اتصال خارجي |
| صيغ محدودة | EAN/UPC وCode128/39 وITF وQR وDataMatrix فقط: أسرع وأقل أخطاءً |
| قراءة جزء من الإطار | قصّ مركزي بدقة معتدلة (≤900px) ~15 قراءة/ثانية: سرعة بلا سخونة |
| بطاقة واحدة = عدّة واحدة | الباركود لا يُعدّ ثانية ما دام ظاهراً؛ يُعدّ من جديد بعد أن يغيب (صندوق جديد بنفس الملصق) |
| تأكيد الرموز الضعيفة | Code128/39/ITF/DataMatrix تحتاج قراءتين متتاليتين |
| بلا انتظار الشبكة | العدّ يحدث على الجهاز فوراً ويُحفظ مع الإذن (تحذير عند مغادرة الصفحة بتعديلات غير محفوظة) |
| GS1 | مسح واحد يعطي الصنف والتشغيلة (وتاريخ الانتهاء) معاً |
| تغذية راجعة | صوت واهتزاز ولون مختلف للنجاح والتكرار والتحذير والخطأ، والمنتج يُظهر `الاسم — المعدود/المطلوب` |
| الكاميرا | الخلفية، تركيز مستمر، مصباح وتكبير 1×/2×/3× عند توفرها (تُفحص ولا تُفترض)، تبديل الكاميرا ويُحفظ اختيارها |
| بطارية وخصوصية | الشاشة تبقى مضاءة أثناء المسح (Wake Lock)، وتُحرَّر الكاميرا عند إخفاء التبويب، وتتوقف تلقائياً بعد 90 ثانية بلا مسح |
| نمطان | **مستمر** (الجرد والتحضير) و**واحد بواحد** (استلام وتحميل: يتوقف بعد كل مسح حتى «مسح التالي») |
| الماسح اليدوي | حقل الكتابة يعمل بنفس المنطق (ماسحات لوحة المفاتيح) |

**HTTPS شرط للكاميرا على الجوال.** في الإنتاج ضع التطبيق خلف HTTPS (Caddy / Nginx / Cloudflare). للتجربة من جوال على الشبكة:
شغّل نفقاً (`cloudflared tunnel --url http://localhost:3000` أو ngrok)، أو في Chrome على الجوال فعّل
`chrome://flags/#unsafely-treat-insecure-origin-as-secure` وأضف عنوان الجهاز. من الحاسوب نفسه يكفي `localhost`.
إن لم تكن الصفحة آمنة يشرح التطبيق السبب بدل أن يفشل بصمت.

الاختبار: `e2e/camera.spec.ts` يشغّل Chrome بكاميرا وهمية تبثّ ملف فيديو فيه باركود EAN-13 حقيقي ويتحقق من العدّ الفعلي
(مرة واحدة أثناء الظهور، ومرة ثانية بعد الغياب، ثم الصنف الآخر). `e2e/scan-engine.spec.ts` يختبر منطق العدّ وGS1.

## التشغيل

```bash
cp .env.example .env.local     # ثم املأ ODOO_URL و ODOO_API_KEY و SESSION_SECRET
npm install
npm run dev                    # http://localhost:3000  (أول زيارة: إنشاء مدير النظام)
```

ربط أودو: ثبّت `supply_api`، أنشئ مستخدم تكامل (مجموعة *Supply Orders / Manager* + صلاحيات المحاسبة والمخزون)، ولّد له
مفتاح API، واضبط المعامل `supply_order.service_user_id` برقم المستخدم. (التفاصيل في `custom_adons/supply_api/README.md`).

## الاختبارات

```bash
npx playwright test            # 14 سيناريو في متصفح Chrome حقيقي
```

تعمل الاختبارات على **أودو تجريبي** (`e2e/mock-odoo.mjs`) بنفس شكل ردود `supply.api` حسب `docs/API_CONTRACT.yaml`،
فلا تحتاج خادم أودو. تغطي: الإعداد الأول، الدخول، إنشاء أمر وتأكيده وتسليمه وفوترته، المسح، التعديل بسبب، الاستبدال،
الطباعة، الأدوار والصلاحيات (وفرضها في الخادم)، التنبيهات، التسوية، الخصومات المؤجلة، منع التكرار. لقطات الشاشة في `e2e/shots`.
الاختبار على أودو الحقيقي خطوة منفصلة (تحتاج مفتاح API).

## نسخة سطح المكتب (لاحقاً)

صُمّم التطبيق ليُغلَّف دون إعادة كتابة: الخادم مستقل (`NEXT_OUTPUT=standalone npm run build` ثم
`node .next/standalone/server.js`)، وبياناته المحلية في `DATA_DIR`، والإعدادات من متغيرات البيئة. غلاف Electron/Tauri
يشغّل هذا الخادم محلياً ويفتح نافذة عليه، ويحفظ `ODOO_URL` والمفتاح في مخزن مفاتيح النظام.

## ملاحظات تقنية

Next.js 16 مع `cacheComponents` معطّلاً عمداً (كل الشاشات حيّة وخاصة بالمستخدم). الاتجاه RTL، الخط Cairo، والأرقام
لاتينية داخل نص عربي (`.num`).
