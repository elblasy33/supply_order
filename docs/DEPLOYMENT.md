# دليل النشر والتشغيل — نظام أوامر التوريد

لمن؟ الفريق التقني الذي يجهّز **قاعدة أودو التجريبية** ويرفع **تطبيق الويب** على حاوية باسم نطاق.
المتطلبات والخطوات بالترتيب، مع طريقة التحقق بعد كل خطوة.

## 0. ما الذي سيعمل وأين

```
جوال/حاسوب ──HTTPS──► Caddy (حاوية) ──► تطبيق Next.js (حاوية) ──JSON-2 + مفتاح API──► أودو 20 (خادمكم)
                                              └─ قاعدة SQLite صغيرة: مستخدمو التطبيق وأدوارهم (مجلد /data)
```

* أودو يبقى مصدر البيانات الوحيد. التطبيق لا يخزّن أوامر ولا أصنافاً.
* مفتاح API لا يغادر خادم التطبيق (يُحفظ مشفّراً).
* أي أودو 20 (Community أو Enterprise) فيه الموديولات يصلح للربط: يُضبط الاتصال من واجهة التطبيق نفسها.

## 1. المتطلبات

| | |
|---|---|
| خادم التطبيق | Linux، ‏2 vCPU و2 GB ذاكرة تكفي للتجربة، Docker 24+ مع Docker Compose v2 |
| الشبكة | نطاق فرعي (مثل `supply.company.com`) بسجل `A` يشير لعنوان الخادم؛ المنفذان **80 و443** مفتوحان (80 مطلوب لإصدار الشهادة) |
| أودو | الإصدار **20**، ويصل إليه خادم التطبيق (HTTPS يُفضَّل). التطبيقات: المبيعات، المشتريات، المخزون، المحاسبة |
| الأجهزة | Chrome (أندرويد) أو Safari (آيفون) حديثان. **الكاميرا والتثبيت يتطلبان HTTPS** |

## 2. تجهيز أودو

### 2.1 نسخ الموديولات وتثبيتها
1. انسخ المجلدات الثمانية من المستودع (`github.com/elblasy33/supply_order`) إلى مسار الإضافات في خادم أودو:
   `document_enhancement`، `supply_order`، `product_tracking_plus`، `smart_alerts`، `invoice_customization`، `discounts_rebates`، `smart_reconciliation`، `supply_api`.
   (المجلد `supply_web` هو التطبيق، ليس موديول أودو، فلا حاجة لنسخه إلى أودو.)
2. أعد تشغيل أودو، وفعّل «وضع المطوّر»، ثم **التطبيقات ← تحديث قائمة التطبيقات**.
3. ثبّت الموديول **`supply_api`**؛ يجلب معه كل الموديولات الأخرى. أو من الأوامر (على قاعدة تجريبية فقط):
   `odoo-bin -c odoo.conf -d <DB> -i supply_api --stop-after-init`
4. تحقق: *التطبيقات* تعرض الثمانية «مثبَّتة»، وقائمة **أوامر التوريد** ظاهرة في أودو.

> تثبيت `supply_api` يثبّت أيضاً `sale_stock` و`purchase_stock` و`product_expiry` و`account`. تأكد أن الشركة مضبوطة محاسبياً (مخطط حسابات، يومية بنك) قبل التجربة.

### 2.2 مستخدم التكامل ومفتاح API
1. **الإعدادات ← المستخدمون ← جديد**: اسم `Supply Integration`، مستخدم داخلي، المجموعات: **Supply Orders / Manager** مع صلاحيات المخزون (مدير) والفواتير (فوترة) والمبيعات والمشتريات المطلوبة.
2. من ملفه الشخصي ← **Account Security ← New API Key**: اسم المفتاح `supply_web`، **انسخ المفتاح فوراً** (لا يظهر ثانية).
3. **الإعدادات ← تقني ← معاملات النظام ← جديد**: المفتاح `supply_order.service_user_id`، القيمة: رقم هذا المستخدم. (يخبرك التطبيق برقمه عند الفحص إن نسيته.)
4. تحقق من الطرف: 
   ```bash
   curl -s -X POST https://ODOO/json/2/supply.api/info \
     -H "Authorization: Bearer <KEY>" -H "Content-Type: application/json" \
     -d '{"context":{}}'
   ```
   يجب أن يعيد `{"ok": true, "data": {"major": 20, ...}}` مع `modules` كلها `installed`. إن كان للخادم أكثر من قاعدة أضف الترويسة `-H "X-Odoo-Database: <DB>"`.

### 2.3 إعدادات وبيانات تُراجَع مع العميل
* اللغات المفعَّلة في أودو (التطبيق يطلب العربية/الإنجليزية من المتاح؛ بلا `ar_001` يستخدم أي `ar_*`).
* الحسابات المقترحة للخصومات المؤجلة: *الشركة ← الخصومات والمكافآت ← إنشاء الحسابات واليومية المقترحة* ثم مراجعتها مع المحاسب.
* باركودات الأصناف **EAN-13 صحيحة** (مجموع التحقق)، والتشغيلات وتواريخ الصلاحية، وقاعدة الخصم الشرطي إن لزم.

## 3. نشر التطبيق على حاوية باسم نطاق

```bash
git clone git@github.com:elblasy33/supply_order.git
cd supply_order/supply_web/deploy
cp .env.example .env
# عدّل .env:
#   DOMAIN=supply.company.com
#   SESSION_SECRET=<ناتج: openssl rand -base64 48>
#   APP_TZ=Africa/Cairo
docker compose up -d --build
docker compose ps          # web يجب أن يصبح healthy، caddy يعمل
docker compose logs -f caddy   # يظهر استخراج الشهادة لنطاقك
```

**التحقق بعد التشغيل**
1. افتح `https://<DOMAIN>`: قفل الشهادة صحيح، وتُحوَّل لصفحة «الإعداد الأول».
2. أنشئ حساب **مدير النظام** (احتفظ بكلمة المرور).
3. **الإعدادات ← الاتصال بأودو**: أدخل عنوان أودو (واسم القاعدة إن لزم) والمفتاح ← **فحص وحفظ**. تنجح الخطوات الخمس:
   الوصول ✓ · الإصدار 20 ✓ · قبول المفتاح ✓ · موديول التوريد ✓ · مستخدم التكامل ✓.
4. مؤشر **«متصل بأودو»** أخضر في الشريط الجانبي.
5. **الإعدادات ← المستخدمون**: أنشئ مستخدمي التجربة وعيّن أدوارهم (راجع «الأدوار والصلاحيات»).
6. من جوال: افتح الرابط، سجّل الدخول، اضغط «تثبيت» (أو «إضافة إلى الشاشة الرئيسية» في آيفون)، وجرّب الكاميرا في «أمر جديد».

> إن لم تُعبَّأ `ODOO_URL/ODOO_API_KEY` في `.env` فالاتصال يُضبط من الشاشة (وهو الأفضل: المفتاح يُحفظ مشفّراً في قاعدة التطبيق).

## 4. التشغيل اليومي

| المهمة | الأمر |
|---|---|
| الحالة والسجلات | `docker compose ps` · `docker compose logs -f web` |
| إعادة التشغيل | `docker compose restart web` |
| **تحديث** لنسخة جديدة | `git pull && docker compose up -d --build` (الأجهزة المثبَّتة تتحدث عند إغلاق التطبيق وفتحه) |
| **نسخة احتياطية** لبيانات التطبيق | `docker run --rm -v supply-orders_app-data:/data -v "$PWD":/backup alpine tar czf /backup/app-data-$(date +%F).tgz -C /data .` |
| استعادة | أوقف `web`، افرغ المجلد، `tar xzf` داخل الحجم نفسه، ثم شغّله |
| تدوير مفتاح API | ولّد مفتاحاً جديداً في أودو ثم الإعدادات ← الاتصال ← الصقه ← فحص وحفظ |
| نسيان كلمة مرور مدير | مدير آخر يعيد ضبطها من المستخدمين. إن لم يوجد: يُحذف سجل المستخدم من `app.db` (يتطلب خبرة SQLite) أو تُستعاد نسخة احتياطية |

* **ما الذي يجب نسخه احتياطياً؟** (1) قاعدة أودو كالمعتاد، (2) حجم `app-data` (مستخدمو التطبيق وأدوارهم). لا شيء آخر.
* تغيير `SESSION_SECRET` يُخرج الجميع من الجلسات **ويُبطل المفتاح المحفوظ** (يُعاد إدخاله من شاشة الاتصال).
* المنطقة الزمنية للوحة المؤشرات من `APP_TZ`.

## 5. الأمان

* لا تفتح على الإنترنت إلا 80/443 للتطبيق. أودو نفسه يكفي أن يكون مفتوحاً لخادم التطبيق (يمكن حصره بعنوان الخادم).
* HTTPS إلزامي؛ الكوكي يُرسل بوسم `Secure` (المتغير `SESSION_SECURE=1` مفعَّل في compose).
* مستخدم التكامل بصلاحيات محدودة بما يلزم فقط، وفي قاعدة التجربة فقط.
* لا تُشارك `.env` ولا المفتاح؛ `.env` غير مرفوع في git.

## 6. استكشاف الأعطال

| العَرَض | السبب والحل |
|---|---|
| لا تُصدَر الشهادة | سجل `A` لا يشير للخادم، أو 80/443 مغلقان. `docker compose logs caddy` |
| الكاميرا لا تعمل / «اتصال آمن» | الصفحة ليست HTTPS (عنوان IP أو http). استخدم النطاق |
| اللون الأحمر «أودو غير متاح» | الخادم لا يصل لأودو: جرّب `curl` من داخل الحاوية `docker compose exec web node -e "fetch(process.env.ODOO_URL||'<URL>').then(r=>console.log(r.status))"` وراجع الجدار الناري |
| «مفتاح أودو مرفوض» (401) | المفتاح خاطئ أو منتهٍ أو لمستخدم آخر. ولّد مفتاحاً جديداً |
| 404 على `supply.api` | `supply_api` غير مثبّت، أو للخادم عدة قواعد: اكتب اسم القاعدة في شاشة الاتصال |
| «اضبط معامل service_user_id» | عيّن المعامل برقم صاحب المفتاح (يعرضه الفحص) |
| «Invalid language code» | لغة غير مفعّلة في أودو. يتجاوزها التطبيق تلقائياً؛ إن ظهرت حدّث `supply_api` |
| باركود لا يُقرأ | مجموع التحقق خاطئ (EAN-13)، أو إضاءة ضعيفة (جرّب المصباح/التكبير) |
| الأرقام لا تطابق أودو | راجع المنطقة الزمنية `APP_TZ`، ومرشح الفترة في اللوحة |
| بعد التحديث يبقى الشكل القديم | أغلق التطبيق المثبَّت وافتحه (التحديث لا يُفعَّل أثناء العمل عمداً) |

## 7. بدون Docker (بديل)

```bash
cd supply_web
npm ci
NEXT_OUTPUT=standalone npm run build
cp -r .next/static .next/standalone/.next/ && cp -r public .next/standalone/
SESSION_SECRET=... SESSION_SECURE=1 DATA_DIR=/var/lib/supply-web PORT=3000 node .next/standalone/server.js
```
ويُوضع خلف Nginx/Caddy بـ HTTPS. يلزم Node 24+ (يستخدم `node:sqlite` المدمج).

## 8. ما بعد التجربة

بعد اعتماد العميل: قاعدة الإنتاج وخادمها، نسخة جديدة من هذا الدليل بنطاق الإنتاج، مفتاح API جديد لمستخدم تكامل الإنتاج، تدريب جميع الموظفين، وتشغيل متوازٍ أسبوعاً قبل القطع.
